# Compact validity browser qualification

This protocol qualifies compact source validity using actual Chromium Workers,
retained native sample/validity arrays and the independent source-mask oracle.
Its imagery remains **quality-rejected-diagnostic-only**. It makes no complete
viewer, GPU rendering, latency, timing, process RSS or scheduling claim. Each
context uses the repository's established Vulkan hardware Chromium flags and
records an actual WebGPU adapter obtained from `navigator.gpu.requestAdapter`.
Missing, fallback or software adapters fail the hardware-environment check.
This identifies the environment; it does not prove mask rendering correctness.

The new runner imports the inherited plan, request geometry, tile selection,
pixel comparison, metric checks and strict pressure predicate from
`tools/viewer-acceptance-browser-masks.mjs`. The original protocol and results
remain immutable. Run `node --test tools/tests/representation-efficiency-browser-masks.test.mjs`
for authored preparation checks; importing either module never launches a browser.

## Cohort and disposition

Use the five inherited representations in their original order and all 2,212
retained regional requests, covering seven levels, component selections,
cross-tile windows and clipped edges. Fetch all 1,883 catalogue masks and compare
actual compact HTTP bodies with the retained bitmap bytes and independent oracle
plane hashes. Constant-mask expansion is bounded to one tile in the comparator;
it is not production Worker memory and does not support a total-process claim.

Retain missing, corrupt and stale mask fault contexts. Add one separate context
that cancels the first Boca RGB16 request when its first mask fetch reaches the
proxy, then executes the same region with a fresh token. Cancellation must emit
one `Cancelled`, no decode, zero retained request reservation/pin bytes and an
exact successful recovery. All terminal jobs require observed zero reservation
and pin bytes. Absent fields do not prove release.

The inherited pressure context is unchanged: **47 windows, two passes, 1 MiB**,
original ordering, no output shrinkage, splitting, raised budget or scheduler
change. Retain the strict inherited completion predicate. Each oversized failure
must separately identify required image-bin bytes, mask bytes, their sum and the
1,048,576-byte limit. Safe rejection remains an excluded failed job. Scoped mask
qualification can finish with explicitly recorded pressure exclusions only when
all other jobs agree, release is observed, actual mask eviction/refetch occurs,
and every pressure failure is a fully accounted oversized request. This is never
reported as 47/47 pressure completion.

There are ten serial contexts/Workers and 2,311 planned terminal jobs, no warmups
or runner retries. Existing bounds remain 60 seconds/job, 660/context,
6,000/invocation, two concurrent HTTP requests, 128 HTTP requests/job and
8 MiB/body (16 MiB catalogue). Normal compressed cache is 64 MiB; descriptor
metadata is 16 MiB, regional decoded pairs 4 MiB, codec workspace 64 MiB.

## Frozen inputs and protected storage

The input schema is `representation-efficiency-browser-masks-input/1`. It retains
the inherited capsule fields for native evidence, Chromium, Playwright, static
assets, service and build identities. Each representation entry now supplies its
fresh compact `root` and a pinned `conversion` file identity. The conversion
receipt binds legacy and compact roots/TIDs, image and descriptor persistence,
mask states and byte/hash catalogues. Native arrays remain in their original
approved store. The new manifest must use `source-validity-v2` with `0:SHA`,
`1:SHA`, or `2:SHA` entries and the corresponding leading payload state byte.

The build receipt includes `runtime_commit` and `tree`; the source checkout must
be clean at that committed candidate before execution. Static files and Chromium
are hashed before and after execution; native references are pinned before and
when served, then rechecked. The frozen protocol includes this document, the new
runner/tests and the imported legacy module. Do not run against mutable source.

Fresh protected groups use `representation-efficiency-browser-masks-<slug>` and
matching `-execution` names beneath the approved RarePlanes store. Each carries
reviewed attribution and lineage. The private Linux `/tmp` bind uses the inherited
verified device/inode, effective mount-ID and private namespace checks with the
new group prefix. Profiles, temporary files, caches, receipts and reference
traffic stay in that approved group. No protected cleanup is performed here.

The invocation receipt schema is `representation-efficiency-browser-masks-grant/1`;
it binds the exact candidate, four protocol SHA-256 values, capsule/plan digests,
fresh output name, one invocation, ten launches, zero retries and operation owner.
It records existing user authority, not a new permission gate. Validate inputs
with `node tools/representation-efficiency-browser-masks.mjs validate --capsule PATH`.
The browser owner starts and monitors the service and executes the runner once
inside the verified private mount namespace with the hardware Chromium setup.

## Evidence and later confirmation

Results retain actual HTTP masks and native array comparisons as bounded counts
and hashes, never pixel dumps outside their authorised store. Persistence fields
separate image payload, descriptors, old/new masks, old/new manifests, total bytes
and new state metadata. Worker delivery, current/peak compressed and mask bytes,
metadata, codec workspace, WASM linear memory, reservations and pin metadata are
reported separately. Runtime timing fields are omitted; no speed claim follows.

A complete scoped result with oversized pressure exclusions exits zero and names
them in `pressure.exclusions`; strict pressure completion remains explicitly
false. Missing agreement, lifecycle, resource or identity evidence exits two.
Retain every attempted context and setup failure. Do not retry a measured outcome.
After landing, verify the merged owner tree and use the same pinned static/binary
identities for the smallest reusable confirmation; a different tree requires a
new bounded probe and new receipt rather than relabelling candidate evidence.
